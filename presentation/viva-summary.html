Microservices often suffer from anti-patterns: design mistakes such as services sharing one database or being so tightly linked they must be deployed together. Research has catalogued 58+ of them (Taibi, Lenarduzzi & Pahl, 2020).

  • Gap 1 – No cloud-native integration: analysis tools run on fixed servers instead of pay-per-use serverless platforms, which studies show can cut costs by 20–40%.
  • Gap 2 – No multi-tool orchestration: tools don't share results, so findings are duplicated, conflicting or missed.
  • Gap 3 – Limited validation: most studies test one tool on small examples rather than several real projects.
↓

💡 The solution

☁️ Cloud-native, serverless-style architecture
Event layer→ Orchestration→ Analysis→ Integration→ Reporting
Multi-tool integration: SonarQube + Roslyn + ArchUnit concepts in one pipeline, with one report.
  • Docker simulation of AWS serverless: each container plays the role of a Lambda function or AWS service (PostgreSQL ≈ RDS, MinIO ≈ S3, Redis ≈ ElastiCache), so there were no cloud costs during the research. It was approved by the course leader.
  • Real pattern detection on the actual source code of each project, not pre-set answers.
  • Normalisation + conflict-resolution design: all tool results are converted into one format, then duplicates are matched by location, pattern type, description similarity and timing.

🎯 Key contributions

  • NEW cloud-native architecture that orchestrates several static-analysis tools in one pipeline
  • PROOF OF CONCEPT Docker-based simulation of AWS serverless for analysis workloads
  • RELIABLE conservative detection with zero false positives in validation
  • OPEN SOURCE full code on GitHub

Honest limits: simplified tool concepts rather than full SonarQube/Roslyn/ArchUnit API integration; small validation set; Docker doesn't reproduce Lambda cold starts or scaling limits.

The story: Found 3 research gaps → Designed the architecture → Built a working prototype → Tested on 4 real projects → Shared it as open source
